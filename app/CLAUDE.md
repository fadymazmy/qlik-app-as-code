## Sheets

- A Sheet file is `{qProperty, qChildren}` holding only this project's overrides. The build merges each object over `defaults/<qType>.json`, the Qlik client's full default tree for that type, because the client does not fill in missing defaults and a partial tree crashes bar and combo charts. An object of a new type needs its default file.
- `app/header.json` holds the Navigation Bar (row 0) and the filter strip of Year, Business Group, Region and Channel (row 1). The build puts it on every Sheet and prefixes its object ids with the Sheet id, so rows 0 and 1 of the 24 x 12 grid are taken on every Sheet; a Sheet's own objects start at row 2.
- The Sheets appear in the Navigation Bar in `rank` order, under their `qMetaDef.title`.
- A cell gives only `col`, `row`, `colspan` and `rowspan`; the build adds the `bounds` Qlik also needs.
- A colour in a Sheet, in a property or inside a colour expression (`If([Sales YTD vs Budget %] < 0, '@neg', '@pos')`), is a theme variable from `theme/theme.json` `_variables`. Qlik resolves theme variables only inside the theme (the engine returns `'@pos'` as it is), so the build writes each one's colour in its place and fails on a name the theme lacks. It replaces every `@word` in every string of a Sheet, so write no other text with `@` in it. A colour expression compares the master measure the column shows, by name, instead of rebuilding it.

## Alternate states

- An object joins an alternate state by `qStateName` on its root (a filter pane and each of its listboxes, and on `qHyperCubeDef`/`qListObjectDef` too). The Customer and Region Sheet uses `A` and `B` for its side-by-side comparison. Each side is a layout container (`sn-layout-container`, one grid cell) titled with its letter, holding that side's filter pane and KPIs as children (each child has a `childRefId`, and the container's `objects` place it in percent); the container itself has no state, its children do. Each side colours its values in its own accent (theme variables `@comparisonA`, `@comparisonB`).
- The build adds every state the assembled objects name with `qlik app state add`, before `qlik app build`, and only those `qlik app state ls` does not list, so a rebuild adds nothing. A state declared only in the app properties is listed but does not work, and `unbuild` does not export states.
- qlik-cli cannot select inside an alternate state (`app eval … where` selects in the default state). So verify evaluates in states from the signed-in capture browser: `valtera/state_check.js` opens its own engine session on the App, selects each side's values (`COMPARISON` in `valtera/verify.py`) in its state and a further selection in the default state, then evaluates every master measure the state's objects show in a hypercube of that state. Each result must equal the Reference calculator's for that side's selection. It runs with the Sheet capture and is skipped with it (`--no-capture`).

## Data files

- The generated CSV files go to one folder per distinct data set, `valtera-data-<hash>/` in the space's DataFiles, where the hash covers every file's name and bytes. The build points `vDataFolder` at it. Builds of the same data share the folder and send only the files it lacks (a file of the same name and size counts as present), so a new app name normally uploads only its claim marker; changed data gets a new folder, so no build overwrites data another app loads. Never write into a `valtera-data-*` folder by hand.
- Each upload is resumable, prints its elapsed time every 30 s, is stopped after 2 minutes plus the file at 20 KB/s (about 29 minutes for `sales.csv`) and tried 5 times in all, a minute apart (a stopped upload stays locked, HTTP 423, for a while), each retry resuming where the last stopped. Only the `.csv` files are uploaded: the tenant refuses zip and gz, and the load script reads only CSV.
- Each build claims its folder with a marker `valtera-data-<hash>/apps/<app-name>.txt`. `clean <app-name>` removes that app's marker from every folder, and a folder only when no other app's marker is left in it. A rebuild after the data changed leaves the app's marker in the old folder, so that folder stays until `clean`. A folder no app claims is never touched by `clean`; a person removes it.

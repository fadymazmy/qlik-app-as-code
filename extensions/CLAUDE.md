## Custom Extensions

- Each extension is one folder `extensions/<folder>/` with `package.json` (`name` = the folder, `main` = `dist/<folder>.js`, `@nebula.js/stardust` as a peer dependency) and `src/index.js` (a nebula.js supernova). The nebula CLI is installed once in `extensions/package.json`; dependencies an extension bundles go there too. Tests go in `<folder>/test/*.test.mjs` (Node's test runner, run by `tests/test_extensions.py`).
- The build runs `nebula build` and then `nebula sense` in the folder, renames the output to `<app-name>-<folder>` (qext `name` and file names), zips it as `<name>/...` and creates or patches the extension on the tenant with `qlik extension create|patch --file`. `clean` removes it again.
- In `app/`, refer to an extension by its folder name (`visualization`, `qInfo.qType` and the cell `type`); the build replaces it with the tenant-wide name. Give the object `disableNavMenu: true` so Qlik's hover menu does not cover it.
- An extension only draws. It reads sheets, selections and data from the App through nebula hooks (`useApp`, `useLayout`, `useNavigation`), and its colours and font from the theme through `themeStyle(theme)` in `extensions/shared.js`, which gives every theme variable `@<name>` as the CSS custom property `--<name>`, with the value in `theme/theme.json` as the fallback for a missing one. Put text into HTML through `esc()` from the same module. It never edits the theme and never makes a network request: no URLs, fonts or scripts from outside the bundle.
- When something renders differently from what the code says, check the extension's own DOM in the browser first (for example a theme value containing quotes breaks an unescaped `style` attribute).
